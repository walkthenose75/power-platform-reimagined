2 · Source

No source — you'll describe the concept in the next step.

A solution almost always relies on things stored outside it. This sets how far the kit follows that chain of dependencies while it documents the solution.

Everything it depends on: the solution and everything it needs to run — SharePoint lists, connections, child flows, custom connectors, external APIs, and the deeper assets those rely on. Safest choice for a faithful rebuild.

Solution + one hop out: the solution plus the items its components reference directly (a list, a connector, a child flow). Deeper or indirect dependencies are not chased.

Only what's inside the solution: just the components packaged in the export. Fastest, but anything external the solution relies on can be missed.

3 · Target

Where and how it gets rebuilt. Custom experiences are built as code apps.

iAlso builds a Microsoft Teams app package (manifest + icons) that embeds the code app as a personal tab — so people can open it from Teams' left rail instead of only in a browser. Optional: the app still works in the browser either way. Note: the app's CSP frame-ancestors must allow teams.microsoft.com, or the tab renders blank.

Fluent UI 2 (@fluentui/react-components v9) makes the code app look first-party in Power Apps and Teams, syncs the Teams light/dark/high-contrast theme, and is accessible by default. Pick Custom only if the demo needs a distinct brand.

Agent work is done through Copilot Studio skills. The harness is where those skills run, and each one supports a different set of actions.

Standard harness: the full agent harness (for example, Copilot CLI). Supports the complete skill set — multi-agent authoring (Advisor, Author, Manage, Test), clone / pull / push / publish, and background evaluation and chat testing.

GitHub Copilot harness: runs the skills inside GitHub Copilot in VS Code. Single-agent and interactive — no autonomous sub-agents or background runs, so some lifecycle actions (publish, batch evaluation) are manual or limited.
